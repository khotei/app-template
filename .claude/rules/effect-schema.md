# Effect: schemas and failures

## Schemas

- An invariant a check can state goes in the schema (`Schema.isTrimmed()`, `Schema.isPattern(…)`,
  a brand), so the constructor and every decode of a row enforce it.
- Brand with `Schema.brand`, never the `Brand` module, so `make`, the row's decode and the api's
  endpoints agree. An id is a branded `Schema.String.check(Schema.isUUID())`, built by
  `buildIdSchema` of `@app-template/packages/schema` given the brand, a contract's too
  ([composition.md › Minimal means inside each unit](composition.md#minimal-means-inside-each-unit)),
  and generated by the generator a service yields from its `idGenerator` once in its `make`; a
  constrained value a port or use case accepts (a file name, a media type, a size) is a brand
  too.
- An absent value is an `Option` (`Schema.OptionFromNullOr(…)` in a model, `null` in its row),
  never `null` or `undefined` in code; `null` exists only in a row and on the wire.
- An annotation a JSON Schema must carry sits on the encoded side, on the key of a checked field
  (`annotateKey`): `annotate` on a check or a transformation drops it. Its test reads it back from
  `Schema.toJsonSchemaDocument`.
- A closed set of stages or kinds is `Schema.Literals([...])`; a subset is `.pick([...])` of it,
  tested with `Schema.is(Subset)`.

## Failures

- A refused operation is a typed failure: never a `throw` (a defect that reads as an infrastructure
  failure) and never an `Option.none` (no detail for the caller or the log).
- A domain error is a `Schema.TaggedError` tagged with its class name, so the api's endpoint
  serves it as it is, with the status the endpoint gives it (`apps/CLAUDE.md`). A marker that
  never leaves its module is `Data.TaggedError`.
- Not-found from a repository or a port is a value (`Option`, or an id left out of an array);
  its reader turns it into the domain's `*NotFoundError`. A `*NotFoundError` carries the key of
  its read; a read by another key raises its own.
- A client's failure, or a stored value that no longer decodes, is a defect where it is read.
  Failures a caller settles differently get a class each, raised after the retries of the
  service over the client (or a port's adapter); failures it does not tell apart, one.
- One name per failure and value: a failure keeps its own error, never one that only wraps it
  nor a table from error tags to a second list; a schema has no alias; and a field nobody reads
  (no code branches on it, no operator looks at it) is not written.
- A failed record keeps its failure as the full text of what ended it (a provider's message, a
  defect's trace), for operators; it never reaches the user, as every wire shape that carries
  the record omits it ([record](../../docs/knowledge/decisions.md#a-failed-run-keeps-its-text)).
