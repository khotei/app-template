# Effect: its API, schemas and failures

This is Effect 4, not the Effect 3 you remember: check every API against the vendored
`repos/effect` (start at `repos/effect/LLMS.md`), never memory. Grep a name you remember in
`repos/effect/migration/v3-to-v4.md`; a changed concept has a guide in `repos/effect/migration/`,
schemas, the HTTP API and config a long one in `repos/effect/packages/effect/` (`SCHEMA.md`,
`HTTPAPI.md`, `CONFIG.md`). What a release may break:
`repos/effect/MIGRATION.md › Unstable Module System`. Check Drizzle against
`repos/drizzle/drizzle-orm/src` (its rc line changes), any other package in
`<workspace>/node_modules/<pkg>`: the isolated linker leaves the root without it.

## Modules

- Code over a value uses the module named for its type (`Array as Arr`, `String as Str`,
  `Struct`, `DateTime`, …); a purpose uses the module named for it: a condition `Predicate`, a
  check that narrows or maps `Filter`, three arms or more `Match`, sorting and extremes `Order`,
  sameness `Equivalence`, merging two `Combiner`, folding many `Reducer`, a nested update
  `Optic`, success or failure as data `Result`, text for a log `Formatter`, composing `Function`.
  Look one up in `repos/effect/packages/effect/src/<Module>.ts` (its first comment, its exports
  with examples); `repos/effect/ai-docs/src/` shows them in use.
- Native code → the module it misses: an accumulator in a loop or `reduce` → `Arr`, `Reducer`;
  a spread that appends → `Arr.append`, one that rebuilds a nested object → `Struct`, `Optic`;
  filter then map → `Arr.filterMap`, `Filter`; `flatMap(Option.toArray)` → `Arr.getSomes`;
  `JSON.stringify` in a log → `Formatter`. A lone default stays `??`, a `null` branch a ternary.
- A utility type comes from effect's `Types`, then `type-fest`. A type built from others
  (`Pick`, `Omit`, `Partial`, an intersection) is wrapped in `Types.Simplify`, so a hover shows
  its fields; an `interface … extends` and a generic helper's own mapped type need none.

## Schemas

- An invariant a check can state goes in the schema (`Schema.isTrimmed()`, `Schema.isPattern(…)`,
  a brand), so the constructor and every decode of a row enforce it. Brand with `Schema.brand`,
  never the `Brand` module, so `make`, the row's decode and the api agree. An id is a branded
  UUID built by `buildIdSchema` of `@app-template/packages/schema`, generated by its model's
  insert variant ([models.md](models.md)); a constrained value a port or use case takes (a file
  name, a size) is a brand too.
- An annotation a JSON Schema must carry sits on the encoded side, on the key of a checked field
  (`annotateKey`): `annotate` on a check or a transformation drops it. Its test reads it back
  from `Schema.toJsonSchemaDocument`.
- A closed set of stages or kinds is `Schema.Literals([...])`; a subset is `.pick([...])` of it,
  tested with `Schema.is(Subset)`.

| What may be absent | Its spelling, which `exactOptionalPropertyTypes` holds apart | Never |
|---|---|---|
| a model's value (a column that is null) | an `Option` (`Schema.OptionFromNullOr(…)` in a model) | `null` or `undefined` for it in code: `null` exists only in a row and on the wire |
| a narrowing a caller may leave out (a query-string parameter) | an absent key of the service's `where`, `key?: T` ([repositories.md](repositories.md#a-wheres-two-forms)); a caller holding `T \| undefined` (`Schema.optional(…)` in the api's schema) builds the object without the key, as the next row shows | an `Option`, which is not "the caller passed nothing"; a helper that cleans `undefined` out |
| a key of an object: `key?: T` alone means the key is absent | the object built without the key: `{ id, ...(note === undefined ? {} : { note }) }` | `{ id, note: undefined }`, a cast, `!` |
| nothing: a key or an owner | a required field, where an `undefined` does not compile | `?` or `\| undefined` on it |

## Failures

- A refused operation is a typed failure: never a `throw` (a defect that reads as an
  infrastructure failure) nor an `Option.none` (no detail for the caller or the log).
  ```diff
  - readonly find: (id: OrderId) => Effect.Effect<Order | null>  // absent as null, no reason
  + readonly getOne: (where: OrderWhere) => Effect.Effect<Order, OrderNotFoundError>
  ```
- An error that reaches the wire is a `Schema.TaggedError` tagged with its class name, so the
  api serves it as it is, with the status its endpoint gives it (`apps/CLAUDE.md`); one that
  never reaches the wire is a `Data.TaggedError`. Not-found from a repository or a port is a
  value (`Option`, an id left out); its reader turns it into the `*NotFoundError` that carries
  the key of its read alone, one error whichever key the read takes.
- A failure and an `Option` cross once: an absent value that fails is
  `Effect.fromOption(() => new <Model>NotFoundError(…))`, never an `Option.match` whose arms are
  `Effect.fail` and `Effect.succeed` alone; a failure is recovered in its flow's tail
  (`effect-style.md › Errors and logs`), never turned into an `Option` its own flow then branches on.
- A client's failure, or a stored value that no longer decodes, is a defect where it is read.
  Failures a caller settles differently get a class each, raised after the client call's
  retries; failures it does not tell apart, one.
- One name per failure and value: never an error that only wraps another, a table from error
  tags to a second list or a schema alias; a field nobody reads (no branch, no operator) is not
  written. A failed record keeps the full text of what ended it, for operators, and every wire
  shape omits it ([decision](../../docs/knowledge/decisions.md#a-failed-run-keeps-its-text)).
- Inspect a `Cause` by its predicates, never by walking it (`repos/effect/migration/cause.md`).
